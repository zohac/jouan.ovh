## 2. Analyse approfondie des stories (patterns transverses)

1. **Construire les pages = test d'intégration des fondations Epic 2.** Deux corrections ont dû *remonter* dans l'Epic 2, révélées seulement par un consommateur réel :
   - **`ZCard` n'avait aucun `:focus-visible`** (seulement `:hover`) — invisible tant qu'aucune carte n'était rendue en lien focusable. Révélé par 3.3 (cartes-projets en `<a>`). Fix dans `app/components/ui/ZCard.vue` (`.zcard--interactive:focus-visible { box-shadow: var(--ring-accent) }`), sans effet de bord (les cartes services 3.2 ne sont pas focusables).
   - **Le dégradé legacy de `default.vue`** (anciens tokens SCSS `_color.$`) débordait derrière les premières sections transparentes — révélé par 3.2. Fix : `background: var(--bg-page)` + retrait de l'import `_color` devenu inutile.
   - Les deux flaggés **« decision-needed »** en revue, **acceptés par Simon**, et tracés vers cette rétro. **Ce n'est pas une indiscipline de périmètre** — c'est la nature d'un épic-page qui exhibe les trous des fondations. Pattern **validé** comme mode de fonctionnement (cf. §6).

2. **L'a11y reste majoritairement attrapée en revue**, malgré la checklist pré-revue (Action 1 d'Epic 2) : focus `ZCard` (3.3), `aria-label` distincts sur 3 liens identiques (3.2), `aria-hidden` sur les prompts décoratifs (3.1), indication « nouvel onglet » (3.3). **Progrès net cependant** : 3.1 a posé `aria-hidden` + focus visible sur la ligne `help` **dès l'écriture**. Limite structurelle : quand le bug est *dans la primitive* (focus `ZCard`), l'écriture de la page ne peut pas le voir.

3. **Trou de vérification VISUELLE — la friction réelle de l'épic.** La story 3.1 (hero) a livré une **régression de padding** : `.hero__in` (`padding: 80px 0`) et `.container` (`padding: 0 24px`), deux classes-layout sur le **même `<div>`**, toutes deux en shorthand `padding` → `.container` (déclarée après) écrasait le vertical → contenu collé sous le header. **La revue de code (4 findings) ne l'a pas vue ; Simon l'a catchée à l'œil** (commit `b45cefb`, fix en longhands `padding-block` / `padding-inline`). Preuve par l'absence : **3.1 est la seule story Epic 3 sans vérif Chrome DevTools MCP** ; 3.2/3.3 l'ont utilisée et n'ont laissé passer aucune régression visuelle. La revue de code est un filet *logique + a11y*, **aveugle au rendu** (padding, débordement, fidélité). → Actions A1 & A2.

4. **Discordance fiche-story vs source de vérité, répétée 3×.** Les 3 fiches citent `max-width: 720px` ; `kit.css` (vérité) utilise `900px`. Le dev a suivi `kit.css` à chaque fois et l'a signalé. Discordance **systématique dans les fiches**. → Action A3.

5. **Conventions qui se propagent proprement.** Clés `v-for` sur `id` stable (établi 3.1 → appliqué 3.2/3.3), repli `forced-colors` local, libellé sr-only « nouvel onglet ». Cohérence intra-fichier tenue. `<component :is>` géré correctement dès 3.1 (import via `#components`) — la leçon Epic 2 est passée dans les réflexes.

6. **`forced-colors`** (rings de focus en `box-shadow` supprimés en contraste forcé) : trou **systémique du DS**, traité localement sur `/`, reporté DS-wide à **Epic 9** (`deferred-work.md`).
